# 主控—用户本地Python—GitHub工作流

更新：2026-09-07。当前阶段见 [CURRENT_STATUS](../CURRENT_STATUS.md)，接管见 [HANDOFF](../HANDOFF.md)。Codex暂停承担新任务，不再作为每轮工作的必经环节。

## 1. 职责

主控负责研究口径、外置代码开发与审查、结果核验、Issue协调及仓库维护；用户在已批准环境执行明确命令，回传去标识化汇总。GitHub保存版本、协议、证据身份与审查；Actions负责轻量CI。私有数据和完整预测留本地。

受控合并由主控在用户授权范围内核对精确HEAD、差异、检查和结论后执行；不直接推送main，不开启自动合并，不把文档PR当作实验PR验收。文档更新不要求用户切分支或拉取。

## 2. 每轮任务

1. 先读当前文档和最新审查，判断任务是否已经完成，防止重复修复、训练或导出。
2. 明确一个任务范围：数据、代码/包、输入SHA、环境、指标、禁止项和停止条件。新下载/训练必须有明确授权。
3. 保护原main未提交修改、任务worktree及数据；文档在独立分支维护。外置包放在worktree之外，不覆盖此前运行目录。
4. 用户本地执行；失败保留现场、错误JSON和检查点，不删锁、不改门槛、不重复启动长任务。修复先判是否只需恢复导出，避免无谓重训。
5. 主控分别核验文件、计算记录、可由汇总复算的统计、实际代码及研究结论。未访问私有数据就明确限定审查范围。
6. 登记协议/包/结果SHA与CI来源。外置文件未提交Git时必须明确说明，不能把评论中的链接/哈希当作源码已发布。
7. **同轮更新当前文档和台账，核对完成后再向用户汇报。**实验未通过也要更新，不只记录好结果。

## 3. 文档生命周期与清理

| 材料 | 维护方式 |
| --- | --- |
| CURRENT_STATUS | 唯一当前状态入口；直接替换失效阶段、阻断、待办与授权说明 |
| HANDOFF | 保留接管必需口径与最新基线，删除已完成任务的现在时指令 |
| README/ROADMAP/code说明/索引 | 同步导航与实现状态，尽量链接台账，避免多份互相矛盾的状态副本 |
| 实验台账 | 记录每次已审交付、结论限制、来源和SHA；不把“接受交付”写成“科学通过” |
| 数据用途台账 | 明确开发/探索/未核验候选，不把已看测试数据重新命名为独立验证 |
| 已冻结协议、结果、错误与SHA | 保存原样及日期，用于复现与追溯；不因落后于新阶段而删除 |
| 失效重复操作说明 | 从当前树内容/导航中删除或合并；旧文本由Git历史追溯，不另造多个“最新”文件 |

至少在验收、故障恢复、输入修订、候选变更、数据盘点及权限变化后触发更新。Issue开放不代表任务仍在执行，PR未合并不代表外置实验未运行。需要保留的历史设计在索引中标为非当前指令，不批量移动以免破坏引用和文献校验。

## 4. 同步与本地资产

被Git忽略、Git状态干净、旧PR已合并，都不等于worktree可删除。清理前必须核实raw/interim/processed及checkpoint，完成备份并获得用户明确批准；本轮文档清理不触碰这些资产。

原运行后的包目录、private、binding、completed或失败记录、恢复ZIP全部留存。恢复工具刻意不补写原completed时，不为补标记重跑。禁止reset/force/批量stash来消除文档分叉。

## 5. 数据与统计底线

输入按发布时间可得信息构造，按时距检查标签成熟；训练转换只在训练窗拟合。统一比较样本，缺测/零分开，获取范围/可分析范围分开；日块统计不把重叠样本当独立日期。

已经查看测试结果后的调参、消融和组合仍是探索性证据。保留负结果、不临时删日或改变门控。新增独立验证在确定候选之后冻结数据范围与评价规则。

## 6. 用户汇报

开头一小段通俗中文说明“现在到哪一步、结果意味着什么、是否需要本地操作”；其后正常提供技术记录。准确说明远端文档是否已合入main、PR是否仍开放、实际做过哪些检查。不将工具记录冒称为主控私有数据复跑，不承诺后台异步交付。
