# Decision Log

## ADR-0001 — 建立统一文献与代码研究库

- 日期：2026-08-27
- 状态：Accepted
- 决策：将文献证据、数据审计、研究缺口、实验代码和版本记录放在同一Git仓库管理。
- 原因：单次搜索不足以支撑论文方向；需要可持续更新和可追溯证据链。
- 约束：不提交未经许可的论文PDF、原始敏感数据或密钥。

## ADR-0002 — 暂不冻结“会话生成+可微调度”方向

- 日期：2026-08-27
- 状态：Accepted
- 决策：该方向保留为候选，但在P0全文审读、数据字段核验和oracle调度价值测试前不作为最终题目。
- 原因：已有灵活性预测、MPC和决策导向工作的先行研究，需要系统比较后才能判断真正创新空间。

## ADR-0003 — 主线转向支持域感知的选择性 OOD 预测

- 日期：2026-08-27
- 状态：Accepted for pilot
- 决策：将“支持域判别—类比站检索—概率预测—拒绝/回退—风险评价”作为下一轮首要门控路线。
- 原因：公开多城市/多站点数据可直接支持；与项目外泛化要求一致；比普通 OOD 或基础模型替换具有更明确的问题结构。
- 限制：通用相邻方法已较成熟，必须通过 EV 特有协议和风险语义证明增量。

## ADR-0004 — 潜在需求方向仅开展可识别性试验

- 日期：2026-08-27
- 状态：Accepted for gate only
- 决策：在确认容量、占用、故障、排队或竞争等删失信息前，不开发复杂潜在需求模型。
- 原因：真实潜在需求不可直接观测，模型复杂度不能替代识别条件。

## ADR-0005 — 联邦学习延后到中央方法验证之后

- 日期：2026-08-27
- 状态：Accepted
- 决策：先证明 OOD/冷启动中央式方法，再考虑异构可信联邦集成。
- 原因：FedMixer、Fed-TREND、FedProC、PiXTime 和联邦保形等已使通用方案高度拥挤；一次叠加将显著提高失败风险。

## ADR-0006 — 将尾部风险并入支持域感知 OOD 主线

- 日期：2026-08-27
- 状态：Accepted for pilot
- 决策：不单独建立普通峰值预测题目，而是在新站点/新城市支持域诊断、概率轨迹和安全回退中加入峰值时间、上尾覆盖和容量越限风险。
- 原因：通用厚尾、跳扩散和选择性学习已较成熟；EV 特有价值在于域外风险和电网阈值语义。

## ADR-0007 — 拥堵与潜在需求方向合并为识别门控

- 日期：2026-08-27
- 状态：Accepted for gate only
- 决策：将可用性、等待、放弃、空间转移和服务功率统一纳入 D2-B/J，但在获得直接运营信号前不开发大型隐变量模型。
- 原因：流体队列、概率排队负荷和删失需求已有先行工作；公开数据的真值缺口是主要风险。

## ADR-0008 — 仿真—真实迁移仅保留为高风险储备

- 日期：2026-08-27
- 状态：Accepted for small pilot
- 决策：允许使用 ACN-Sim、EV2Gym 或机理模拟进行小规模预训练—真实校正实验，但首篇主线仍以真实数据严格 OOD 为准。
- 原因：模拟器可覆盖稀有状态，但其偏差可能被学习模型继承；必须通过独立真实目标域和负迁移诊断证明价值。

## ADR-0009 — 将静态冷启动升级为网络干预结构 OOD

- 日期：2026-08-27
- 状态：Accepted for pilot
- 决策：Gate S 必须同时预测新站与既有站需求再分配，并允许在支持不足时拒绝或回退。
- 原因：新站规划和普通零历史预测已有直接先行工作；节点新增改变整个充电网络的数据生成机制。

## ADR-0010 — 运营车队场站作为平行门控

- 日期：2026-08-27
- 状态：Accepted for parallel pilot
- 决策：以 WeTRaC 和 RouteZero 为基础，验证路线/返回/能耗联合概率是否改善场站鲁棒调度。
- 原因：数据、代码、物理任务和调度指标最清晰，可较低成本判断预测的实际价值。

## ADR-0011 — Performative 方向先做响应可识别性

- 日期：2026-08-27
- 状态：Accepted for gate only
- 决策：没有真实干预数据或外部现场效应约束时，不将仿真闭环结果作为主论文证据。
- 原因：通用 performative 理论和 EV 决策依赖博弈已有先行工作；预设响应函数会主导结论。
