# 数据获取与语义审计清单 — v0.6

## 1. 目标

本清单用于确认数据能否支撑“在充会话—未来到达会话双源滚动概率功率预测”及后续预测—调度闭环。任何模型开发之前，必须完成数据版本、字段语义、预测时刻可用性和控制污染审计。

## 2. 数据源优先级

### 主数据：ACN-Data

重点核查：

- 会话标识；
- 连接时间和断开时间；
- 完成充电时间；
- 已交付电量；
- 测量电流/功率时间序列；
- pilot 或充电导引信号；
- 用户申报需求和离站信息的覆盖率；
- 站点拓扑、EVSE 和容量限制；
- 数据访问许可及 API 版本。

### 独立核验：DESL-EPFL Level 3

重点核查：

- 实际测量功率；
- 请求功率；
- 控制设定功率；
- SOC；
- 控制模式或控制标志；
- 采样间隔和时间同步；
- 车辆、充电桩和会话层级标识；
- 使用许可及引用要求。

## 3. 获取记录

每次获取数据必须记录：

| 字段 | 说明 |
|---|---|
| dataset_id | 数据集唯一标识 |
| source_url | 官方下载/API入口 |
| access_date | 获取日期 |
| release_version | 版本或发布日期 |
| license | 许可和使用限制 |
| raw_file_count | 原始文件数量 |
| raw_size | 原始数据大小 |
| sha256 | 原始文件校验值 |
| timezone | 原始时区 |
| sampling_interval | 原始采样间隔 |
| site_scope | 站点范围 |
| session_count | 会话数量 |
| notes | 访问异常或字段变化 |

不得只保存处理后数据而不保留原始版本标识。

## 4. 字段语义字典

对每个字段建立如下记录：

| 字段 | 说明 |
|---|---|
| raw_name | 原始字段名 |
| canonical_name | 统一字段名 |
| unit | 单位 |
| level | 车辆/会话/EVSE/站点/时间 |
| measured_or_derived | 测量/设定/请求/推导 |
| available_at_issue_time | 发布时间是否可用 |
| missing_rate | 缺失率 |
| transformation | 清洗或转换规则 |
| leakage_risk | 是否存在未来信息泄漏 |
| control_dependence | 是否受历史控制策略影响 |

## 5. 必须区分的功率概念

### 请求功率

\[
P_t^{\mathrm{request}}
\]

车辆、电池或充电接口期望获得的功率。

### 控制设定功率

\[
P_t^{\mathrm{set}}
\]

站控、充电桩或上层优化器下发的允许功率。

### 实际测量功率

\[
P_t^{\mathrm{real}}
\]

实际计量得到的执行功率。

### 站级聚合功率

\[
P_t^{\mathrm{station}}=\sum_i P_{i,t}^{\mathrm{real}}+P_t^{\mathrm{aux}}
\]

需确认是否包含辅助用电、损耗、待机功率和非充电负荷。

任何无法明确区分上述语义的数据，不得直接用于声明“自然充电需求预测”。

## 6. 预测发布时间字段白名单

在发布时间 \(\tau\) 对在充会话允许使用：

- 会话是否已开始；
- 截至 \(\tau\) 的连接时长；
- 截至 \(\tau\) 的实际功率/电流轨迹；
- 截至 \(\tau\) 的已交付电量；
- 当前 SOC（若真实可测）；
- EVSE、接口和额定功率；
- 截至 \(\tau\) 已执行的 pilot/设定值；
- 当前故障和可用状态；
- 已知日历、价格和天气预报。

禁止使用：

- 真实最终断开时间；
- 真实最终完成充电时间；
- 真实最终交付电量；
- 预测时刻之后的功率、SOC或控制信号；
- 由完整会话事后计算、但实际在线不可获得的标签。

## 7. 时间与采样审计

必须完成：

- 原始时区确认；
- 夏令时处理；
- 时间戳重复和倒序检查；
- 会话跨日处理；
- 采样间隔分布；
- 功率/电流积分与交付电量一致性；
- 重采样造成的峰值削弱；
- 缺测插值对标签的影响；
- 多站点时钟同步。

## 8. 会话—站级一致性审计

对每个站点和时间窗检查：

\[
\sum_i P_{i,t}^{\mathrm{real}}
\]

是否与站级计量功率一致。记录：

- 平均绝对差；
- 最大差；
- 辅助负荷或损耗解释；
- 缺失会话比例；
- 不一致时间段。

若无站级计量值，则需明确“站级功率由会话求和重构”，并将该误差边界写入实验结论。

## 9. 控制污染审计

统计：

- \(P^{\mathrm{set}}<P^{\mathrm{request}}\) 的时段比例；
- pilot 限制发生比例；
- 站级功率约束生效比例；
- 控制前后功率差；
- 不同控制策略对应的数据段；
- 设备故障或通信异常。

根据结果将数据分为：

1. 近似无控制自然充电；
2. 可识别历史策略下的执行功率；
3. 控制语义不明，不适合作为主要标签。

## 10. 数据切分原则

- 训练、验证、测试按时间切分；
- 不允许将同一完整会话的前后片段分到不同集合；
- 标准化统计量只用训练集；
- 参数选择只用验证集；
- 测试集不得参与阈值、场景数或校准参数选择；
- 多站点结果应同时报告逐站和聚合指标。

## 11. Gate 0 通过标准

至少满足：

- 一个数据集具有高分辨率真实测量轨迹；
- 能识别预测时刻仍在充的会话；
- 能构造严格无泄漏的滚动输入；
- 测量功率、设定功率和请求功率的语义可以解释；
- 会话与站级聚合关系可核验或可明确限定；
- 数据许可允许研究使用和结果复现。

若 Gate 0 未通过，应先更换数据源或缩小研究问题，不进入模型开发。
