## 1. 实际完成的功能

新接口像一层“翻译和信息检查”：只让当前时刻已经发生、已经收到的人工事件进入控制器视图，保留缺测、延迟和假设标记；无法确认单位、设备对应关系或请求含义时明确阻断。它没有决定何时充电、充多少电，也没有连接真实数据或设备。

| 层次 | 实现与边界 |
| --- | --- |
| 时间与会话 | 分开记录发生时间和可用时间；先过滤再读取值；确定性处理修订与冲突。迟到断开不提前关闭会话；收到后关闭。同一设备不能同时属于两个连接会话；关闭的会话身份不能重新连接并沿用旧电流。 |
| 不可变视图 | `build_synthetic_controller_view` 只接受 `synthetic-controller/v1` 人工输入，返回不可变的映射会话；拒绝整个评价真值对象。输出固定 `synthetic_only=true`、`real_dispatch_authorized=false`。 |
| 身份与单位 | 设备需要 site/cluster/station/space 四项键及有效期映射。电流与 pilot 分开；A/Ah 不能改名为 kW/kWh。固定窗均值与实际覆盖时段均值分别保存。 |
| 需求与支撑 | 总量、追加量及未知语义分开处理；追加量需要修订时交付基点。声明过期、语义不明或缺少离站信息有明确状态。区间检查要求显式连续支撑，但不验证预测质量或情景概率。 |
| 功率假设 | 仅允许显式单接口电压/PF 假设生成 `assumed_proxy`；不存在实测功率准入实现。不同计量边界不能直接比较。 |

上述时间、来源及单位标签仍由调用方声明。格式检查不能证明原始来源、接收时间、计量精度或许可真实有效，也不是权限系统。

## 2. C01–C15 实际结果

[聚合报告](evidence/controller_adapter_checks_20261106.json) 记录每项实际观察值、源码 SHA256、运行时间及状态。15 项全部通过，含主动构造的拒绝路径；没有读取真实会话、最终电量或保留集。

| 场景 | 人工检查得到的结果 |
| --- | --- |
| C01 迟到观测 | 当期保留原来的 3 A；到收到该记录的后续时点才更新为 9 A。 |
| C02 未知接收依据 | 缺少可用时间被拒绝；显式回放保持 `assumed_replay` 标签。 |
| C03 修订冲突 | 输入重排不改变最新声明；同时间、同修订的冲突值被拒绝。 |
| C04 迟到断开 | 未收到通知时保留连接并标记陈旧；收到后移出当前连接集合。 |
| C05 电流与 pilot | 3 A 实际电流与 8 A pilot 可并存，不把命令值当作实测电流下限。 |
| C06 区间支撑 | 5 个稀疏区间不能冒充 16 个连续区间；完整连续时间支撑被接受。 |
| C07 未来与评价真值 | 改动未来事件值、最终电量和离站等评价值，或加入不可得的坏映射内容，当前控制器视图保持相同；整个真值对象不能作为接口输入。 |
| C08 电气假设 | 拓扑相角作为 PF 依据、额外三相倍率被拒绝。 |
| C09 设备身份 | station/space 字符串相同不能替代有效映射。 |
| C10 覆盖口径 | 900 A·s 在 900 秒固定窗内为 1 A，在 300 秒覆盖时段内为 3 A；分别保存。 |
| C11 能量计数 | 回零和计数周期切换被拒绝；正常 5→6 kWh 增量为 1 kWh。 |
| C12 请求语义 | 未知语义和 Ah 单位被拒绝；总目标 10、已交付 3 得 7 kWh；追加 5、基点 2、当前已交付 3 得 4 kWh。 |
| C13 用途越界 | 归档电流或假设功率不能被导出为实测功率。 |
| C14 显式代理量 | 手填 4 A、208 V、PF=1 得 0.832 kW，始终标记为假设代理量。 |
| C15 计量边界 | EVSE 边界与包含待机、损耗的上游边界不能直接视为一致；相同声明边界通过也不代表完成电表校准。 |

## 3. 复现与验证记录

使用此前工程检查的独立 Python 3.11.16 环境，本轮没有安装或升级软件。新增适配器和验收入口只依赖标准库，可用 `-S` 禁用 site-packages 后运行。已有输出文件会被拒绝；失败记录为 FAIL 并非零退出。

从仓库根目录运行以下单行命令，输出路径须尚不存在，父目录须存在：

```powershell
python -S scripts/check_controller_adapter.py --output controller-adapter-local.json
```

该命令只执行人工场景，不接收数据集或模型路径。CLI 测试还拦截了 Python socket 连接/DNS 接口，并注入单项故障验证“14 通过、1 失败、进程失败”的行为；这是应用层检查，不是操作系统级断网证明。优化模式 `-O` 不会关闭验收判据。

新增 79 项测试在禁用 site-packages 后全部通过；连同本 PR 原有 26 项工程测试，本机共 **105 项测试、277 个子用例通过，无跳过**。12 个新增 Python 文件的 Ruff 和语法检查通过。默认环境及两个冻结环境的完整包名称/版本列表前后一致；这不是对所有安装字节的审计。

检查命令、文件哈希、独立规格/质量审查和旧环境包元数据比较见 [验证记录](evidence/controller_adapter_validation_20261106.json)。本机检查只覆盖本 PR 的工程文件；远端整库 CI 的精确 HEAD 和结果单独记在 PR 正文中，不用定向测试替代整库 CI。

## 4. 仍然没有证明的内容

- 15 项通过只验证这里实现的行为，不代表草案 G1–G9 的真实数据准入门全部通过。没有实际获取或审计 ACN 样本，没有独立接收日志，也没有电压/PF/计量校准证据。
- 未来内容不影响当前视图，以用于筛选的时间字段合法、完整为前提；缺失或非法时间仍被拒绝，不会猜成“未来记录”后忽略。
- `state_age_seconds` 是距最近任意可见事件的时间，并非每个电流/pilot 通道的观测年龄；不能据此判定每个数值足够新。`DECLARED_ONLY` 也不代表服务需求可行。
- 当前同刻排序在相同时间与修订号下先连接、再观测、最后断开。同设备跨会话在完全相同时间交接会被保守拒绝；同刻跨事件种类使用不同修订号也可能因顺序被拒绝。这不是物理上不可能的结论，需另行约定同刻交接与跨种类修订语义后扩展，不能擅自挪动时间戳消除冲突。
- 连续 16×15 分钟只验证人工时间支撑；没有概率预测生成、权重校准、时间依赖验证或真实四小时预测轨迹。该时域和步长仍是可调整的样例配置。
- 功率、能量和计量边界函数是独立的严格检查；未串成设备动作、求解器、配网潮流和闭环评价。没有证明成本下降、削峰、服务满足或电网安全性。
- 辅助资源、最终题目、创新点、求解器、时域及配网公式继续待研究；本轮不能据此选定 HVAC 或工业负荷。
