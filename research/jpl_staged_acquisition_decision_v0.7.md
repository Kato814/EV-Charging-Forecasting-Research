## 为什么不能随机抽取少量会话代替连续窗口

当前任务是站级日内滚动预测：

\[
P_{\tau+h}=P^{\mathrm{active}}_{\tau+h}+P^{\mathrm{arrival}}_{\tau+h}.
\]

若只随机下载单条会话，会破坏同一时刻的并发关系，无法恢复：

- 站级总功率；
- 在充会话集合；
- 未来到达会话集合；
- 峰值和爬坡；
- 预测发布时间信息边界。

因此，站级 Gate 必须使用**完整连续时间窗内的全部会话**。随机或分层抽样仅可用于单会话剩余轨迹模型，不可替代站级评估窗口。

## 加速获取路径

### 路径 1：官方 API 分块获取——当前主路径

- 当地月按日建立独立文件和 manifest；
- 完整历史 carry-in 会话采用精确 `sessionID` 查询；
- 支持断点续传、已有文件跳过和失败重试；
- 默认串行，必要时并发不超过 2 个工作线程，尊重 429/Retry-After；
- 每个日块完成后立即执行完整性检查，不等全月结束后再检查。

### 路径 2：静态镜像作为备选批量来源

候选镜像：`tongxin-li/ACN-Data-Static`。

其 JPL 目录包含约 27,723 个单会话压缩 CSV，字段包括：

- Charging Current (A)；
- Actual Pilot (A)；
- Voltage (V)；
- Energy Delivered (kWh)；
- Power (kW)。

使用条件：

1. 先选不少于 100 个会话，与官方 API `/ts` 对齐核验时间戳、电流、pilot 和累计电量；
2. 记录镜像 commit SHA；
3. 原始镜像不得重新分发；
4. 论文仍引用官方 ACN-Data；
5. 镜像缺少独立许可文件，必须遵守官方 ACN-Data 使用条款；
6. 静态镜像主要覆盖 2018—2020，2021数据仍需官方API。

当前 100 会话预检只验证了官方 API 数据质量，并未完成官方 API 与镜像逐字段一致性核验。因此，除非官方 API 完整月获取时间不可接受，否则不切换镜像。

## 功率语义约束

- `chargingCurrent` 是实测电流，不是直接的 kW 有功功率；
- `pilotSignal` 是导引/控制信号，不是实测功率；
- 在获得并核验 EVSE 电压、相别、功率因数和网络配置前，只能形成站级电流聚合或代理量，不能将其表述为站级实测有功功率；
- 功率标签构造必须与 `kWhDelivered` 做积分一致性校验。
