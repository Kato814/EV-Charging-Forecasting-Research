# 主控—本地Codex—GitHub工作流

当前任务与例外见 [CURRENT_STATUS](../CURRENT_STATUS.md) 和 [HANDOFF](../HANDOFF.md)。

## 职责

主控负责问题、数据与评价口径、代码/证据审查、Issue协调和有条件合并；本地Codex负责授权范围内实现、私有数据处理和实验执行；GitHub提供版本与证据交接，Actions只跑轻量CI。代码提交、CI通过、科学验收是三件事。

## 每轮任务

1. 先读真实仓库状态和最新评论，冻结一个Issue、任务分支、数据范围、禁止项和交付证据。
2. 本地使用独立worktree及已批准环境。用户原工作区不动；任务worktree有未知修改则保护并诊断，不批量stash/clean。
3. 主控与Codex不同时向同一活动分支修改生产代码。长任务运行时不要求同步新main；文档维护另用分支。
4. 本地执行记录实现commit、配置与snapshot SHA、环境、随机种子、日志和续跑状态。失败不删证据、不改阈值凑PASS。
5. 仅提交代码、测试、配置和允许的去标识化汇总；检查暂存区，禁止raw、完整预测、模型、私有ID、Token及本地绝对路径。
6. Codex推送并创建/更新原PR，不自动合并；主控读取实际差异、证据、对应HEAD的CI和阻断处理。
7. 通过后合并、更新CURRENT_STATUS/HANDOFF和Issue；未通过继续同一任务，不另建重复PR。

## 同步与本地资产

保留raw、interim、processed和checkpoint；它们可能位于任务worktree而非独立共享根目录。`git status`干净不代表没有数据。合并PR后也不得自动删除worktree；必须先列出被忽略数据、确认备份/迁移和本地引用，再由用户批准清理。

文档main可能与运行中的数据分支产生普通分叉。待进程结束、工作区干净再进行非破坏性同步；不能假定永远可fast-forward，更不能用reset/force消除分叉。文档变更不自动要求重跑正式实验，但合并提交的CI仍要核对。

## 数据与统计底线

所有输入按发布时间可得信息构造。训练/验证/测试按时间及标签实际可用时刻划分，变换仅在训练窗拟合。统一比较样本、指标方向和缺测语义；日块统计不能把重叠15 min样本冒充独立日。缺测与实测零分开，获取完整性与分析可用性分开。

主控未取得本地raw时只能声明复核远端代码和提交证据，不能宣称独立复算私有数据。依赖本地私有快照的CI skipped测试须有对应本地记录。

## 文献流程

保留 `检索→去重→筛选→全文审读→证据提取→可检验假设`。新增文献记录来源、核验日期、审读深度、局限并运行校验；不能把摘要阅读标为全文审读，不上传无再分发许可全文。文献更新不自动改动冻结实验协议。
